ETAP 1 — ODBIORNIK KOMISU Z APLIKACJI ROBOCZEJ

Co przygotowano:
- netlify/functions/receive-commission.mjs — funkcja Netlify przyjmująca zdjęcia i pełny zestaw ogłoszeń.
- netlify.toml — wskazuje katalog funkcji Netlify.
- data/komis.json — początkowy, pusty plik danych publicznych.
- cztery strony HTML pobierają dane z data/komis.json w trybie publicznym.
- każda podstrona wyświetla wyłącznie swoją kategorię: cars, motorcycles albo other.
- usunięto widoczny przycisk „Wróć do panelu” ze strony publicznej.

WAŻNE — JESZCZE NIE PUBLIKUJ TEJ PACZKI.
Funkcja jest przygotowana, ale wymaga skonfigurowania sekretów Netlify i testu na bezpiecznej gałęzi testowej. Nie wykonano rzeczywistego zapisu do GitHub, ponieważ wymagałoby to dostępu do tokena i ustawień Twojego konta.

KONFIGURACJA NETLIFY (po uzgodnieniu testu):
Site configuration → Environment variables

Dodaj:
1. GITHUB_TOKEN — fine-grained personal access token z dostępem Contents: Read and write do repozytorium budwel-coder/komis. Token nie może trafić do kodu HTML ani do aplikacji iPhone.
2. GITHUB_OWNER = budwel-coder
3. GITHUB_REPO = komis
4. GITHUB_BRANCH = komis-test (wymagana gałąź testowa; funkcja nie ma domyślnej gałęzi)
5. ALLOW_PRODUCTION_IMPORT = true — NIE DODAWAJ podczas testów. Włączymy dopiero po osobnej zgodzie na import do main.
6. IMPORT_PASSWORD = długie, losowe hasło, które będzie znane tylko administratorowi i wpisywane przy wysyłaniu z aplikacji.
7. IMPORT_ORIGIN = https://budwel-coder.github.io

IMPORT_ORIGIN to sam origin GitHub Pages — bez końcowego /komis/.

Po dodaniu lub zmianie zmiennych Netlify trzeba wykonać deploy funkcji. Nie rób tego, dopóki nie przygotujemy i nie sprawdzimy aplikacji wysyłającej.

JAK DZIAŁA PROTOKÓŁ:
1. Aplikacja wysyła zdjęcie jako data URL do akcji upload-photo.
2. Funkcja tworzy obiekt Git blob i zwraca ścieżkę pliku oraz SHA.
3. Aplikacja przygotowuje ogłoszenia, w których photos i thumbnails zawierają ścieżki galeria/... zamiast Data URL.
4. Aplikacja wywołuje akcję publish z tablicami cars, files i obiektem siteSettings.
5. Funkcja tworzy jeden commit z plikiem data/komis.json i wszystkimi przesłanymi zdjęciami.
6. Commit uruchamia automatyczne wdrożenie Netlify. Ponieważ Netlify i GitHub Pages są obecnie podłączone do tego samego repozytorium, commit może również uruchomić publikację GitHub Pages.

WALIDACJA:
- obsługiwane kategorie: cars, motorcycles, other;
- limit pojedynczego zdjęcia po kompresji: 4 MB;
- limit ogłoszeń: 1000;
- limit zdjęć na jedną publikację: 5000;
- sprawdzane są hasło, origin, identyfikatory plików i ścieżki zdjęć.

OGRANICZENIA:
- aplikacja iPhone nie jest jeszcze częścią tej paczki;
- nie wykonano prawdziwego testu publikacji w GitHub/Netlify;
- panel administratora nadal zapisuje dane lokalnie w IndexedDB — odbiornik nie synchronizuje starego panelu;
- stare zdjęcia, które nie są już używane przez nowe ogłoszenia, nie są automatycznie kasowane z repozytorium;
- nie wysyłaj tokena GitHub ani hasła importu w wiadomości lub w kodzie strony.
